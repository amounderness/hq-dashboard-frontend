# Switchboard website update · stages 01–03 · 26 September 2026

The Leeds pilot now follows the agreed sequence: 01 close source gaps and clarify Forecast; 02 owner release controls; 03 reports and exports; 04 small viewer pilot; 05 expansion beyond Leeds; 06 Forecast model development. Stages 01–03 are in progress. This is a website and workflow release; the active `leeds-pulse-v0.4.0` data package is unchanged.

Forecast is now named simply **Forecast**. It explains the current prior-ward-share benchmark, historical holdout testing, the meaning of average share error, and why the weak 2026 holdout does not support a prospective 2027 prediction. It describes future party-specific evaluation, uncertainty ranges and repeated simulations as planned research, without a fixed numerical accuracy target. Vote counts, seats and council control are later model stages.

Data & sources now links to a [Leeds source-issue register](leeds-source-issues-2026-09-26.md). The blank Farnley & Wortley 2024 council-hosted declaration, 15 historical candidate-vote differences and uncertified by-election coverage remain open. The currently published results and quality notes have not been silently changed.

The new **Owner releases** screen is only shown to the account whose Cloudflare Access JWT matches the configured owner email. The server checks the Access signature, issuer, audience and email again on each administration request; all writes also require same-origin JSON requests. It accepts a built package folder rather than raw spreadsheets. Each JSON object must match the manifest hash and is immutable by release ID. Validation checks all object hashes, basic ward and geography joins, election references, candidate and party vote totals, and manifest counts. The screen shows object-level differences and release limits against the active package. The owner records an approval reason for the exact manifest hash; activation repeats validation and conditionally changes the R2 pointer using its ETag. Audit records are written before and after approval, activation and rollback. Rollback can restore the prior release for an activation made through this new screen. Earlier releases still use the documented manual recovery pointer.

**Reports** offers a ward result brief, dated council composition and recorded SDP results, each with a print/save-PDF view and CSV download. Reports identify the package and election view, preserve source/quality context, and do not turn missing results into zero votes. CSV escaping neutralises spreadsheet formula-looking cells. The reports use the same approved package objects as the Explorer.
