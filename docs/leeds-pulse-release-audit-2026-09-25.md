# Leeds Pulse release audit · 25 September 2026

This audit covers the separately built immutable `leeds-pulse-v0.3.0` release. The original `leeds-local-elections-v0.1.0` development package remains unpublished. The release includes public election results, official 2025 ward geometry, 2021 Census aggregates, and the project's exploratory K=7 Electoral Tribes ward aggregation. Forecast is unchanged and remains a retrospective test summary only.

## Census and Electoral Tribes

The [ONS Census 2021 topic summaries](https://www.ons.gov.uk/census/aboutcensus/censusproducts/topicsummaries) provide output-area counts. The [ONS OA21-to-WD25 best-fit lookup](https://www.data.gov.uk/dataset/4cb87107-de5a-4ee5-bc78-d7bd3fb86f67/output-area-2021-to-ward-2025-to-lad-may-2025-best-fit-lookup-in-ew-v3) assigns those areas to 2025 wards. A fresh official Leeds query on 25 September 2026 returned 2,607 output areas. Every output-area-to-ward code agreed with the research lookup: 2,607 matches, zero differences. The 33 derived ward profiles include 17 Census measures with counts, denominators and shares. The allocated population totals 811,964, eight above the native Leeds Census figure of 811,956; best-fit geography assignment and Census perturbation can explain such a small difference, so the UI does not portray it as a new population estimate.

The project's `k7_oa_geo_cluster_base_v1.csv` assigns each output area to one of seven exploratory groups. Ward proportions are weighted by each area's 2021 residents. All 33 ward group shares sum to one within numerical tolerance. These groups are statistical descriptions of neighbourhood Census patterns, not individual profiles or voting intentions. They are labelled as exploratory in the interface.

The local build audit records SHA-256 hashes for the source files and the fresh official lookup in `audit-downloads/leeds-pulse-v1/audit.json`. The newly downloaded lookup is `23e65ef509fe961c7a887b79f6e29cccf48ea8ab620b1cf7c0af30769eb2fdb6`. The published `pulse/ward-profiles.json` object is `54f4e391c661f21155259f93187e64796ebaed7027926482c68e15280f9fecd0`. Exact byte equality between the local raw Census extracts and upstream current downloads was not established. The lineage is documented at dataset and geography-join level, not as an upstream byte certification.

## Election quality and gaps

The release contains 166 recorded contests and 938 candidate records across 2021–2026. The existing [results audit](leeds-release-audit-2026-09-25.md) details the 15 candidate-vote differences between the 2021–2024 Commons Handbook files and the Leeds council archive. Four affected ward/year records now carry their own quality notes in the Explorer: 2021 Kirkstall, 2023 Calverley & Farsley, 2023 Headingley & Hyde Park, and 2024 Roundhay. The release keeps the Handbook values and exposes the discrepancy. Council clarification has not been obtained.

The [Leeds City Council archive](https://datamillnorth.org/dataset/local-election-results-20jwj) includes a 10 October 2024 Farnley & Wortley by-election PDF, but its declaration has zeroes for all votes and no winner. The event is visible in ward history as **result source rejected**, with a direct source link; no totals were invented. The 12 June 2025 Morley South by-election is included as a recorded result. The [22 October 2026 Calverley & Farsley by-election notice](https://www.leeds.gov.uk/elections/leeds-city-council-elections) is shown as **upcoming**, without an outcome. The by-election register is not certified exhaustive. “Latest recorded” means latest imported poll, not present councillor composition.

## Validation and publication gate

The release builder verifies all 2,607 output areas, 33 ward joins, Census denominator bounds, tribe shares and result invariants. `tools/test_leeds_release.py` rechecks all 33 immutable data objects against the manifest hashes, all 938 candidate records and 166 contests, plus the two special by-election states. Local typecheck, lint, production build and interactive browser checks passed. All 33 private R2 objects were uploaded, read back and hash-checked before the `active.json` pointer was changed. The previous pointer was preserved. The owner-only live Explorer loaded the new package and the SDP-contested filter returned 20 matching wards in the latest recorded view. Signed-out requests for the page, Pulse API and favicon each returned HTTP 302 to Access. The final deployed Worker version was `5ebce1c4-8af3-4537-b0b0-898386e93629`.
