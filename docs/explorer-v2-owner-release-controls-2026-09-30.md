# Explorer v2 owner release controls — 30 September 2026

**Status:** prepared locally on `feature/explorer-v2-owner-releases`; not deployed, approved or activated in Cloudflare. The active Leeds Pulse v0.6.0 package and live v2 feature flags are unchanged.

The owner page now has a separate Yorkshire Explorer v2 panel. Its route, `/api/admin/v2-releases`, requires a verified Cloudflare Access JWT for the configured owner email; writes also require same-origin JSON. The v2 objects live under `v2/releases/<package_id>/`, approvals under `v2/admin/approvals/`, audit entries under `v2/admin/audit/`, and the versioned pointer at `v2/active.json`. Leeds uses different keys and cannot be replaced by these actions. Successful API responses use `private, no-store`.

The screen stages only files named by a schema-1 Yorkshire manifest. It refuses changed bytes at an existing release ID, verifies each object's SHA-256, checks the catalog, geometry, coverage and candidate/contest references, and records validation. Approval needs a written source-review reason and binds to the exact manifest hash. Activation revalidates, requires that exact approval, checks the previous pointer's storage version, and records from/to audit events. A stale page or concurrent pointer change is rejected. Rollback revalidates the previously active package and uses the same storage-version check. A first activation has no previous v2 package; disabling the two v2 feature flags is the recovery route until a second version exists.

Local tests passed the complete stage → validate → approve → activate → rollback cycle, rejection of an unapproved or stale release, immutable staging, tamper rejection, and a full in-memory R2 round trip of the recovered Yorkshire rc3 package: 58 objects, 54 council-years, 1,278 contests and 7,809 candidate records. The existing Leeds release tests, TypeScript, lint, Next.js production build and vinext Worker build passed. Local unauthenticated GET and POST requests to the new owner API returned 403 with private no-store headers. In Chrome, mocked authorized API responses displayed the Leeds and v2 release panels and a completed validation message without page errors. That browser mock checks UI wiring, **not** a real Cloudflare owner session or R2 write. Passing release mechanics does **not** clear the source, by-election, historical geography or licence gates for regional viewer publication.
